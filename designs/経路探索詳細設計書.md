## 2. タイルの仕様（確認済み）

- URL: `https://cyberjapandata.gsi.go.jp/xyz/experimental_bvmap/{z}/{x}/{y}.pbf`。レイヤー `road`。`extent` = 4096。座標は整数。線は外側 80 の余白まで入る
- 応答: `Content-Type: application/vnd.mapbox-vector-tile`。gzip で転送される（日本橋の z14 は 579 KB、転送 179 KB）。存在しないタイル（海など）は 404
- デコード: `@mapbox/vector-tile` ^2.0.5・`pbf` ^4.0.2（2026-11-16 に依存へ追加。`maplibre-gl` が使っている版と同じにして、重複を避けた。試作は 1.3.1・3.2.1 で行ったが、読み出す内容は同じ）
- 使うズーム: **14 だけ**（z15・z16 は同じ線。z16 は道路縁 `22xx`・`24xx` が混ざる。z13 以下は階級が欠ける・つながりが不完全）

### 2.1 属性（地理院の仕様書より）

| 属性 | 値 |
|---|---|
| `rdCtg` | 0 国道 / 1 都道府県道 / 2 市区町村道 / 3 高速自動車国道等 / 5 その他 / 6 不明 |
| `motorway` | 0 高速道路以外 / 1 高速道路 / 9 不明 |
| `tollSect` | 0 無料 / 1 有料 / 2 暫定無料 / 9 不明 |
| `rnkWidth` | 0 3 m 未満 / 1 3〜5.5 m / 2 5.5〜13 m / 3 13〜19.5 m / 4 19.5 m 以上 / 5 その他 / 6 不明 |
| `lvOrder` | 道路の階層順（0 が地表。実測で 0〜3） |
| `medSect` | 0 分離帯なし / 1〜98 分離帯の幅（m）/ 99 非表示 |
| `ftCode` | 2701 通常部 / 2702 雪覆い / 2703 橋・高架 / 2704 トンネル。271x 庭園路、272x 徒歩道、273x 石段（下 1 桁は同じ並び） |
| `orgGILvl` | 2500 / 25000（もとの地図情報レベル） |

実測（東京 9 枚・28,436 本）: `rdCtg = 3` の 870 本は、すべて `motorway = 1` かつ `tollSect = 1`。`rdCtg` が 0〜2 の線に `tollSect = 1` は無かった（一般の有料道路は、この範囲に無かっただけと見られる）。庭園路（2711）が 3,659 本あり、公園・構内の道にあたる。

### 2.2 階級（`RoadClass`）の決め方

上から順に当てはめる。`src/lib/routing/roadClass.ts` の 1 つの関数にまとめる。

```ts
export type RoadClass = 1 | 2 | 3 | 4 | 5 | 6   // 里道 / 市区町村道 / 県道 / 国道 / 有料 / 高速

export function roadClassOf(p: { ftCode: number; rdCtg?: number; motorway?: number; tollSect?: number; rnkWidth?: number }): RoadClass | 0 {
  if (!(p.ftCode >= 2700 && p.ftCode <= 2799)) return 0          // 中心線ではない → 使わない
  if (p.motorway === 1 || p.rdCtg === 3) return 6
  if (p.tollSect === 1) return 5
  if (p.ftCode >= 2710) return 1                                  // 庭園路・徒歩道・石段
  if (p.rdCtg === 0) return 4
  if (p.rdCtg === 1) return 3
  if (p.rdCtg === 2) return p.rnkWidth === 0 ? 1 : 2              // 幅員 3 m 未満の市区町村道は里道（Q4）
  return 1                                                        // その他・不明
}
```

- `tollSect = 2`（暫定無料）は、有料に入れない（`rdCtg` で決まる）
- 石段（273x）は里道に入る。徒歩のルートでは通れるので除かない

## 3. データの持ち方

### 3.1 タイルの中身（`RoadTile`）

デコードした結果から `road` の中心線だけを取り、型つき配列で持つ（建物などは捨てる。1 枚あたり数十〜数百 KB）。

```ts
// src/lib/routing/types.ts
export interface RoadTile {
  x: number; y: number                 // z14 のタイル番号
  count: number                        // 線の本数
  cls: Uint8Array                      // [count] RoadClass
  lv: Uint8Array                       // [count] lvOrder
  struct: Uint8Array                   // [count] 0 通常 / 1 雪覆い / 2 橋・高架 / 3 トンネル（ftCode の下 1 桁 − 1）
  start: Uint32Array                   // [count + 1] coords の中の開始位置（点の番号）
  coords: Int32Array                   // [点の数 × 2] 世界座標（§3.2）。x, y の順
}
```

`roadTiles.ts`:

```ts
export type TileBytesLoader = (x: number, y: number, signal?: AbortSignal) => Promise<ArrayBuffer | null>   // null = 404
export function decodeRoadTile(x: number, y: number, bytes: ArrayBuffer): RoadTile     // 純粋関数。§3.2 の「切る」まで行う
export class RoadTileCache {                                                            // LRU。上限 400 枚
  constructor(loader: TileBytesLoader, opts?: { max?: number; concurrency?: number })  // 同時取得は 6
  get(x: number, y: number, signal?: AbortSignal): Promise<RoadTile>                    // 404 は「空のタイル」を返して覚える
  getMany(keys: { x: number; y: number }[], signal?: AbortSignal, onProgress?: (done: number, total: number) => void): Promise<RoadTile[]>
  has(x: number, y: number): boolean
}
```

- 取得の失敗（通信・5xx）は 1 回だけやり直し、だめなら例外。`routeLeg()` がつかまえて `fallback` にする
- 単体テストでは `TileBytesLoader` を差し替える（保存した実タイル、または手作りの `RoadTile`）

### 3.2 座標と、タイルの境界

- **世界座標**: z14 のタイル番号 × 4096 + タイル内の座標。整数。日本の範囲で 2^26 未満なので、ノードのキーは `wx * 2^26 + wy`（2^52 未満。`number` で正確に持てる）
- **切る**: 各線を、タイルの範囲 [0, 4096] × [0, 4096] で切る（線分ごとの Liang–Barsky）。切り口の座標は四捨五入して整数にする。範囲の外だけを通る線は捨てる。1 本が 2 つ以上に分かれたら、別の線にする
- **境界の縫い合わせ**: 切り口は、両側のタイルで別々に計算されるので、1 格子（z14 で約 0.5 m）ずれることがある。境界の上の端点は、**同じ境界線の上で ±1 格子以内**にすでにあるノードへ寄せる（§3.3 の手順 2）
- 境界の線の上をちょうど通る線は、両方のタイルに入る。辺を足すときに、両端のノード・点の数・長さ（0.1 m 単位）が同じ辺は 1 本にまとめる

### 3.3 グラフ（`RoadGraph`）

足していくだけのグラフにする（タイルを足せる。外せない）。**辺の数が上限（150 万）を超えたら、グラフごと捨てて、いま要るタイルだけで作り直す**（タイルの中身は `RoadTileCache` に残っているので、通信は起きない）。ドラッグのたびに組み立て直さないため（東京 49 枚で 0.45 秒かかる）。

```ts
// src/lib/routing/graph.ts
export class RoadGraph {
  nodeX: number[]; nodeY: number[]               // 世界座標
  nodeLat: number[]; nodeLng: number[]           // 探索の下限の計算に使う（足すときに 1 回だけ計算）
  adj: number[][]                                // ノード → 辺の番号
  edgeA: number[]; edgeB: number[]               // 両端のノード
  edgeLen: number[]                              // m（大円距離の和）
  edgeCls: number[]; edgeLv: number[]; edgeStruct: number[]
  edgeTile: number[]; edgeLine: number[]; edgeFrom: number[]; edgeTo: number[]   // 形: tiles[edgeTile] の線 edgeLine の、点 edgeFrom〜edgeTo
  tiles: RoadTile[]
  hasTile(x: number, y: number): boolean
  addTile(tile: RoadTile): void
  edgeShape(e: number): Int32Array               // 世界座標の点列（a → b の向き）
  get edgeCount(): number
}
```

`addTile()` の手順:

1. タイルの全部の線の両端を集め、キーの集合 `ends` を作る
2. 各線について、端点のノードを決める。端点がタイルの境界の上（タイル内の座標が 0 か 4096）にあるときは、キーが同じノード、無ければ境界線に沿って ±1 のキーのノード（**「境界のノード」の印がついたものに限る**）を探し、あればそれを使う。無ければ新しく作り、境界のノードの印をつける
3. 線の途中の点が `ends` に入っているときは、そこで線を分ける（T 字で切れていない線。実測で 9 枚に 2〜6 か所）
4. 辺を足す（§3.2 の重複を除く）。長さは、世界座標を緯度経度に直して大円距離で足す
5. 両端が同じノードで点が 2 つ以下の辺は捨てる

- **立体交差**: 何もしない。線が交わっていても端点を共有していなければ、つながない（§1 の 5）
- 辺は双方向（一方通行を見ない。方針 Q1）

### 3.4 空間索引（アンカーを寄せるため）

タイルごとに、線分を 256 格子（約 120 m）のマスに分けた索引を、最初に使うときに作って `RoadTile` に持たせる（`WeakMap<RoadTile, SegmentGrid>`）。

## 4. 探索（`search.ts`）

### 4.1 入出力

```ts
export interface SearchParams {
  weight: number[]        // [0, 8.0, 4.0, 2.4, 1.6, 1.2, 1.0]（添字 = RoadClass）
  valley: number          // 2000（m 相当。谷の深さ 1 段につき）
  valleyFloor: RoadClass  // 2（これより下の階級は、この階級として数える）
  maxClass: RoadClass     // 6 / 5（高速を使わない）/ 4（有料も使わない）
  maxExpand: number       // 2,000,000（展開した状態の数の上限。超えたら失敗）
}
export interface GraphPos { edge: number; t: number; lat: number; lng: number }   // 辺の上の位置。t は a からの道のりの割合（0〜1）
export interface SearchResult {
  edges: { edge: number; reversed: boolean; from: number; to: number }[]   // 通る辺と、その中の範囲（t）
  distance: number        // m
  cost: number
  valleys: number         // 罰則を払った回数（試験・調整用）
}
export function search(g: RoadGraph, from: GraphPos, to: GraphPos, p: SearchParams, shouldStop?: () => boolean): SearchResult | null
```

### 4.2 状態

状態 =（ノード `n`, 直前の辺の階級 `c`, これまでの最高の階級 `top`）。`top ≥ c`。番号は `n * 49 + c * 7 + top`（`c`・`top` は 1〜6）。

- 優先度つきキュー（二分ヒープ。キーと値を別の配列に持つ）による A*
- 下限: 終点までの大円距離 × 「使える階級のうち、いちばん小さい重み」
- 最良のコストと、ひとつ前の状態は `Map<number, …>` に持つ（ノード数 × 49 の配列は大きすぎる。試作ではこの形で 1 回 平均 65 ms）
- 500 回の展開ごとに `shouldStop()` を呼び、true なら打ち切る（null）

### 4.3 コストと、谷の罰則（R3）

辺 `e`（階級 `c'`）へ進むコスト = `長さ × weight[c']` + 罰則。

```
lo = max(c, valleyFloor)          // いまいる階級（市区町村道より下は、市区町村道として数える）
hi = min(top, c')                 // 上がった先。ただし、これまでの最高より上の分は数えない
罰則 = (hi > lo) ? valley × (hi − lo) : 0
新しい top = max(top, c')
```

意味: **いったん上の道を走った後で下の道へ降り、また上がる（谷）とき、その谷の深さ（低いほうの縁から底まで）の分だけ罰する。**

| 経路の階級の並び | 罰則 | 説明 |
|---|---|---|
| 市 → 県 → 国 → 県 → 市 | 0 | 山型 |
| 国 → 県 → 国 | 1 段 | 抜け道 |
| 国 → 市 → 国 | 2 段 | 抜け道（より下の道） |
| 国 → 県 → 高速 | 1 段 | 取付道路。国道から見て 1 段の谷。**高速から見た 3 段ではない** |
| 高速 → 県 → 国 | 1 段 | 上の逆。同じ罰則になる |
| 市 → 里 → 市 | 0 | `valleyFloor` より下は数えない |
| 県 → 里 → 県 | 1 段 | 里道は市区町村道として数える |

- 行きと帰りで同じ経路・同じコストになる（試作で、東京 40 組・上田 40 組とも差なし）
- 罰則は「払えば通れる」。上位の道が途切れている・取付道路しかない場所では、谷を通る
- 区間ごとに探索するので、利用者が下の道に経由点を置けば、その前後は罰則なしで通る

**始点・終点が辺の途中にあるとき**:

- 始点: 寄せた辺の両端のノードを、最初の状態にする。コスト = 端までの道のり × 重み、`c = top =` その辺の階級
- 終点: 寄せた辺の両端のノードに着いた状態から、「その辺を終点の位置まで進む」遷移を作る（コスト・罰則は、ふつうの辺と同じ計算）。この遷移の先を、ゴールの状態にする
- 始点と終点が同じ辺の上にあるとき: 辺の上をまっすぐ進む経路を、候補の 1 つとして最初にキューへ入れる

### 4.4 経路の点列

`SearchResult.edges` の順に、辺の形（`edgeShape()`）を、向きと範囲（`from`〜`to`）に合わせて切り出してつなぐ。つなぎ目の同じ点は 1 つにする。世界座標を緯度経度に直す（小数 7 桁に丸める）。先頭と末尾は、寄せた位置（`GraphPos` の `lat`・`lng`）そのものにする。

## 5. アンカーを道へ寄せる（`snap.ts`）

```ts
export interface SnapParams { radius: number; bias: number; maxClass: RoadClass }   // 30 m、15 m
export function snapToGraph(g: RoadGraph, lat: number, lng: number, p: SnapParams): GraphPos | null
```

1. 点のまわり `radius + bias` 以内の線分を、空間索引で集める（`maxClass` を超える階級の辺は除く）
2. それぞれについて、垂線の足までの距離 `d` を求める。**高速（階級 6）とトンネル（`struct = 3`）は `d + bias` として比べる**
3. 比べた値が最小で、かつ `d ≤ radius` のものを選ぶ。無ければ null

- 寄せた位置を、もう一度同じ規則で寄せても同じ辺になる（寄せたあとは `d = 0` なので）。**アンカーは寄せた後の緯度経度だけを持ち、区間の探索のたびに寄せ直す**（辺の番号は、グラフを作り直すと変わるため、持たない）
- null のとき（30 m 以内に道が無い）: アンカーは置いた位置のまま。区間は、300 m 以内の最寄りの辺まで直線で結び、そこから探索する。300 m 以内にも無ければ、その区間は `fallback`（直線）

## 6. タイルを取る範囲と、長い区間（`corridor.ts`・`coarse.ts`）

重いのはタイルの取得（東京の z14 は 1 枚の転送が約 180 KB）なので、**探索の前に「どの z14 のタイルを取るか」を決める**のが、この節の仕事。探索そのものは、いつも z14 のグラフで §4 の規則どおりに行う。

### 6.1 区間の長さによる切り替え

`d` = 始点と終点の直線距離。

| `d` | 方式 | 取るタイル |
|---|---|---|
| 5 km 以下 | 1 段階 | 始点–終点の線分から `r = max(1 km, 0.5 × d)` 以内にかかる z14 のタイル（d = 5 km で約 20 枚） |
| 5 km 超、100 km 以下 | 2 段階（§6.2） | 粗い経路のまわりの回廊（試作で、9〜29 km の区間に 35〜50 枚） |
| 100 km 超 | **探索しない**（`fallback`。理由 `too-long`） | — |

- `r` の根拠: 最適な経路の、線分からの横へのずれ ÷ `d` が、90% 点で 0.45〜0.50（§1）
- 100 km の上限の根拠: 回廊の z14 のタイルが 200 枚を超え、取得が数十 MB になる。**これより長い区間の方式（z9 を使う 3 段階）は試作していないので、入れない**。利用者には「区間が長すぎます。途中に経由点を置いてください（100 km まで）」と知らせる。上限は定数にして、あとで広げられるようにする
- 2 段階で粗い経路が見つからなかったとき: `d ≤ 12 km` なら 1 段階でやり直す。それより長ければ `fallback`（理由 `no-route`）
- すでに取得済みのタイルは、範囲の外でもグラフに入っていれば探索に使われる（結果が良くなる方向にしか働かない）

### 6.2 2 段階の探索

**(1) 粗いグラフ（z12）** — 始点と終点を囲む四角形を、各辺 `max(10 km, 0.25 × d)` 広げた範囲の z12 のタイル（1 枚 約 10 km 四方・20 KB 前後）で作る。z12 には国道・県道・高速だけが入っている。

z12 の線は、そのままではつながらない（§1）。**次の順で補う**（`coarse.ts` の `buildCoarseGraph()`）。試作で、最大の連結成分が 上田 69% → 99%、東京 52% → 98% になった。

| 手順 | 内容 | 値 |
|---|---|---|
| a | §3.2〜3.3 と同じ手順で切って縫い合わせる。境界の許容差は ±2 格子 | |
| b | 近いノードどうしを、長さ 0 の辺で結ぶ | 3 格子（z12 で約 6 m）以内 |
| c | 行き止まり（次数 1）のノードの近くにほかの辺の線分があれば、その辺の両端へ結ぶ（長さ = 両端までの直線距離、階級 = 相手の辺） | 3 格子以内 |
| d | 行き止まりのノードから、近いノード 2 つまでへ「仮の市区町村道」を張る（長さ = 直線距離 × 1.3、階級 2）。z12 に無い市区町村道の代わり | 800 m 以内。自分の辺の両端は除く |

- **b・c では、高速（階級 6）とそれ以外をつながない**（高架の下の一般道と誤ってつながるのを防ぐ）。d では、高速どうしだけをつながない（高速の行き止まり = ランプの終わりを、近くの一般道へつなぐ）
- 粗いグラフは、タイルの組ごとに作って 4 つまで覚える（ドラッグ中に作り直さない）

**(2) 粗い経路** — 始点・終点を、近い粗いノード 6 つまでへ「仮の市区町村道」（直線距離 × 1.3）でつなぐ。探す半径は 1.5 km から始め、3 つ見つかるまで 2 倍ずつ 12 km まで広げる。§4 の規則で探索する。

**高速を使える設定のときは、「高速なし」（`maxClass = 4`）でも探索し、両方の経路を回廊に入れる。** z12 では、インターチェンジのつながりが正しく復元できないことがあり（サービスエリアのランプを出口と見てしまう、など）、高速ありの経路だけを信じると、z14 で大きく遠回りになる場合があった（試作で、コストが 2.3 倍になった例）。高速なしの経路も入れると解消した。

**(3) 回廊** — 粗い経路の線から 1,000 m 以内にかかる z14 のタイルと、始点・終点から 2,500 m 以内にかかる z14 のタイル。

**(4) 細かい探索** — 回廊のタイルを取得してグラフに足し、§4 の探索を行う。最終の線は z14 の中心線だけから作る。

### 6.3 精度（試作の結果）

全部のタイルを使った最適な経路と比べたコストの比（各 20 組。回廊の幅 700 m のとき。東京 9〜20 km、上田 12〜29 km）:

| | 最適と同じ | 5% 以内 | 最悪 | 回廊の枚数（中央値 / 最大） |
|---|---|---|---|---|
| 東京 | 19 | 19 | 1.23 倍 | 35 / 59 |
| 上田 | 15 | 16 | 1.08 倍 | 43 / 63 |
| 上田（幅 1,200 m） | 17 | 18 | 1.07 倍 | 49 / 72 |

- **2 段階の探索は、最適を保証しない**。外れるのは、高速に乗る・乗らないの判断が粗いグラフで違ったとき。利用者は、経由点を足して直せる
- 失敗（経路なし）は 0 組

## 7. 公開 API と Worker

### 7.1 `routeLeg()`（`src/lib/routing/index.ts`。純粋な TypeScript。DOM・Leaflet に依存しない）

```ts
export interface RoutingOptions { avoidMotorway: boolean; avoidToll: boolean }       // → maxClass 6 / 5 / 4。avoidToll は avoidMotorway を含む
export type FallbackReason = 'no-road' | 'no-route' | 'too-long' | 'tile-error' | 'aborted'
export interface RouteResult {
  status: 'ok' | 'fallback'
  points: { lat: number; lng: number }[]     // 両端を含む。fallback は 2 点
  distance: number                           // m
  reason?: FallbackReason
  from: { lat: number; lng: number }         // 寄せた後の始点（寄せられなければ入力のまま）
  to: { lat: number; lng: number }
}
export class Router {
  constructor(loader: TileBytesLoader, coarseLoader: TileBytesLoader)
  snap(lat: number, lng: number, options: RoutingOptions, signal?: AbortSignal): Promise<{ lat: number; lng: number } | null>
  routeLeg(from: LatLng, to: LatLng, options: RoutingOptions, signal?: AbortSignal, onProgress?: (done: number, total: number) => void): Promise<RouteResult>
}
```

- `routeLeg()` は throw しない（`aborted` も `fallback` の理由として返す）
- `points` の先頭と末尾は、**入力の位置そのもの**。道へ寄せた位置が入力と違うとき（30 m 以内に道が無く、300 m 以内の道まで直線で結んだとき）は、その次に寄せた位置が入る
- `snap()` は、点のまわりのタイル（点を含むタイルと、境界まで 30 m 以内なら隣のタイル）だけを取って寄せる
- `avoidMotorway` のとき: 階級 6 の辺を、グラフには入れたまま探索と寄せで無視する（グラフを設定ごとに作り分けない）

### 7.2 Worker（`src/workers/routing.worker.ts`）と、メイン側の窓口（`src/lib/routingClient.ts`）

Worker の中に `Router` を 1 つ持つ。タイルのキャッシュとグラフは Worker の中だけにある。

```ts
// メイン → Worker
type Req =
  | { type: 'snap'; id: number; lat: number; lng: number; options: RoutingOptions }
  | { type: 'route'; id: number; from: LatLng; to: LatLng; options: RoutingOptions }
  | { type: 'cancel'; id: number }
// Worker → メイン
type Res =
  | { type: 'snap'; id: number; point: LatLng | null }
  | { type: 'route'; id: number; result: RouteResult }
  | { type: 'progress'; id: number; done: number; total: number }
```

```ts
// src/lib/routingClient.ts
export function snapAnchor(lat: number, lng: number, options: RoutingOptions, signal?: AbortSignal): Promise<LatLng | null>
export function routeLeg(from: LatLng, to: LatLng, options: RoutingOptions, signal?: AbortSignal, onProgress?: (done: number, total: number) => void): Promise<RouteResult>
```

- `signal` の abort で `cancel` を送る。Worker は、その `id` の `AbortController` を abort する（タイルの取得が止まり、探索は `shouldStop()` で止まる）
- 探索は同期の計算（最大 0.3 秒ほど）なので、Worker は要求を 1 つずつ順に処理する。**待っている要求のうち、すでに `cancel` されたものは、始める前に捨てる**
- Worker を作れない環境（`Worker` が無い）では、`routingClient` が同じスレッドで `Router` を直接呼ぶ（動きは同じ。E2E・古い環境の保険）
- Worker は、最初に経路探索を使ったときに作る（作成モードを開いただけでは作らない）

### 8.4 進行役（`src/lib/draftController.ts`）

非同期の処理（寄せる・探索する・古い結果を捨てる）を、ここにまとめる。コンポーネントは、この関数を呼ぶだけにする。ストアは `useEditorStore.getState()` で読む。

```ts
export function addAnchorAt(map: L.Map, latlng: L.LatLng, opts: { straight: boolean }): void      // クリック。順序を保つ直列のキューに入れる（いまの MapPane のキューをここへ移す）
export function beginAnchorDrag(anchorId: string): void                                           // ドラッグ前の下書きを覚える
export function dragAnchorTo(anchorId: string, latlng: L.LatLng): void                            // ドラッグ中。150 ms に 1 回だけ探索を頼む（最後の位置は必ず頼む）
export function endAnchorDrag(map: L.Map, anchorId: string, latlng: L.LatLng): Promise<void>      // 寄せる → 前後を探索 → 履歴に積む
export function insertAnchorOnLeg(legId: string, latlng: L.LatLng): string                        // つまみのドラッグ開始。新しいアンカーの id を返し、beginAnchorDrag と同じ状態にする
export function removeAnchorById(anchorId: string): void
export function rerouteAll(): void                                                                // auto の区間を、いまの設定で全部引き直す
export function undo(): void
export function redo(): void
export function cancelAll(): void                                                                 // モードを離れるとき
```

**区間の探索を頼む手順**（`requestLeg(legId)`。内部の関数）:

1. その区間の前の要求があれば abort する（`Map<legId, AbortController>`）
2. 区間の `gen` を覚えて `routeLeg()` を呼ぶ
3. 結果が返ったら `setLegResult(draft, legId, gen, result)`。`aborted` は入れない
4. `fallback` になったら、理由ごとのトーストを出す（同じ区間の同じ `gen` につき 1 回）

| 理由 | トースト |
|---|---|
| `no-road` | 近くに道路が無いため、直線で結びました |
| `no-route` | 経路が見つからないため、直線で結びました |
| `too-long` | 区間が長すぎるため、直線で結びました。途中に経由点を置いてください（100 km まで） |
| `tile-error` | 道路データを取得できないため、直線で結びました |

**クリックでアンカーを足す**（キューの中で、順に）:

| 条件 | 位置の補正 | 区間 |
|---|---|---|
| 経路探索 ON・Ctrl なし | `snapAnchor()`。null なら置いた位置のまま | `auto` |
| 経路探索 ON・Ctrl（Cmd）あり | しない | `straight` |
| 経路探索 OFF・Ctrl なし・マップマッチング ON | いまの `matchPoint()` | `straight` |
| 経路探索 OFF・ほか | しない | `straight` |

足す前の下書きを `commitDraft()` で履歴に積む。

**取り消し・やり直し**: 進行中の要求を全部 abort → 下書きを差し替える → `pending` の区間をすべて頼み直す（`gen` を 1 増やしてから）。探索が済んだ区間は、線ごと戻るので頼み直さない。

**ドラッグ中**: ストアの下書きを書き換える（アンカーの位置と、前後の区間 = `pending`）。履歴には積まない。`endAnchorDrag` で、`beginAnchorDrag` のときの下書きを履歴に積む。位置が変わっていなければ積まない。

### 8.5 地図の層（`CreateRouteLayer.tsx` の書き直し）

**毎回すべてを作り直す いまの形をやめ、id で対応づけて使い回す**（ドラッグ中にマーカーを作り直すと、ドラッグが切れる）。

- `Map<anchorId, L.Marker>` と `Map<legId, L.Polyline>` を `useRef` に持つ。下書きが変わるたびに、増えたものを足し、消えたものを外し、残ったものは `setLatLng()`・`setLatLngs()`・`setStyle()` で直す
- **ドラッグ中のマーカーには `setLatLng()` をしない**（`draggingId` を `useRef` に持つ）
- 末尾のマーカーだけ大きい・`#番号` のツールチップは、いまと同じ。番号が変わったらツールチップを直す
- `locked` のアンカーは `draggable: false`・色 `#1e3a8a`・クリックで消えない

| 区間の状態 | 線の見た目 |
|---|---|
| `auto`・`ok` | 実線・`#2563eb`・太さ 4 |
| `straight` | 点線 `6 4`・`#2563eb`・太さ 3（いまと同じ） |
| `pending` | 点線 `2 6`・`#93c5fd`・太さ 3 |
| `fallback` | 点線 `6 4`・`#f59e0b`・太さ 3 |

マーカーのイベント:

| イベント | 処理 |
|---|---|
| `dragstart` | `draggingId` を入れる。`beginAnchorDrag(id)` |
| `drag` | `dragAnchorTo(id, latlng)` |
| `dragend` | `draggingId` を空に。`endAnchorDrag(map, id, latlng)` |
| `click` | `removeAnchorById(id)`（`stopPropagation`。いまと同じ） |

**つまみ（線の上のドラッグで経由点を差し込む）**:

- つまみは `L.Marker`（白い丸・直径 12・青い縁・`draggable: true`）を 1 つだけ作り、使い回す
- 区間の線の `mousemove` で、マウスにいちばん近い線の上の点（`L.LineUtil.closestPointOnSegment` を線分ごとに。画面の座標で）へつまみを動かして見せる。その区間の `legId` を覚える。線の `mouseout` で、つまみの上にマウスが無ければ隠す（つまみの `mouseout` でも隠す）
- 線は細いので、当たり判定用に、同じ形で透明・太さ 16 の線を重ねる（イベントはこちらで受ける）
- つまみの `dragstart`: `insertAnchorOnLeg(legId, latlng)` → 返った id を `draggingId` に入れる。**このアンカーのマーカーは、ドラッグが終わるまで作らない**（つまみがその役をする）
- つまみの `drag`・`dragend`: アンカーのマーカーと同じ処理。`dragend` のあと、つまみを隠す（アンカーのマーカーが作られる）
- つまみをクリックしただけ（`dragstart` が起きない）なら、何も起きない。地図の `click` に伝わってアンカーが足されないよう、`click` で `stopPropagation` する
- アンカーのマーカーから 12 px 以内では、つまみを出さない（アンカーをつかみにくくなるため）
- タッチ端末: 線の `contextmenu`（長押し）で、その位置につまみを出す。3 秒さわらなければ隠す（実機では未確認）

## 10. 下書きの行き先と確定（機能追加・UI改善設計書 B0〜B2 の細部）

操作と決まりは、機能追加・UI改善設計書の B0〜B2 のとおり。ここでは、§8 の型に合わせた関数の形と手順だけを決める。

### 10.1 状態

- `editorStore` に `draftTarget: DraftTarget`（既定 `{ kind: 'new' }`）。`clearDraft()` と、作成・道なり補正のモードを離れる `setMode()` で既定に戻す
- 履歴（`draftPast`・`draftFuture`）には `Draft` だけを積む（行き先は、下書きの途中で変わらない）
- `draftController` に足す関数:

```ts
export function startAppend(routeId: string, trackIndex: number, end: 'tail' | 'head'): void
// 端の点の位置に locked のアンカーを 1 つ置き、draftTarget を append にする。履歴は空にする
export function startReplace(routeId: string, trackIndex: number, startIndex: number, endIndex: number): void
// startIndex < endIndex に並べ替える。両端の点の位置に locked のアンカーを 2 つ置き、間を auto（経路探索 OFF なら straight）の 1 区間として頼む。draftTarget を replace にする
```

- `locked` のアンカーは道へ寄せない（元の点の位置のまま）。`routeLeg()` が、30 m 以内の道へ寄せた点、または 300 m 以内の道までの直線を、区間の線の中に入れる（§7.1）

### 10.2 `applyDraft()`（`src/lib/editors/draftApply.ts`。純粋関数）

```ts
export interface DraftApplyInput {
  target: DraftTarget
  points: TrackPoint[]            // 下書きの点列（draftPoints() に、標高を付けたもの。時刻は付けない）。append の head は「描いた向き」のまま渡す
  newRoute?: { id: string; name: string; trackName?: string; startTime?: Date; endTime?: Date }   // target が new のとき
  speed: SpeedProfile             // B3
}
export type DraftApplyResult =
  | { ok: true; routes: RouteData[]; undoLabel: string; addedPoints: number }
  | { ok: false; error: 'target-missing' | 'too-few-points' }
export function applyDraft(routes: RouteData[], input: DraftApplyInput): DraftApplyResult
export function countWaypointsInRange(points: TrackPoint[], startIndex: number, endIndex: number): number   // 両端を除く。確認ダイアログ用
```

| 行き先 | 手順 | `undoLabel` |
|---|---|---|
| `new` | いまの `handleCreateConfirm` と同じ（`startTime` があれば B3 で時刻を付ける。`endTime` もあれば `redistributeTimeWithRange`）。`points` が 2 未満なら `too-few-points` | ルート作成 |
| `append`・`tail` | `old = track.points`。`add = points.slice(1)`。`old` の末尾に時刻があれば、`[old の末尾, ...add]` に B3 で時刻を付け、その 2 点目以降を `add` にする。`[...old, ...add]` | ルートに追記 |
| `append`・`head` | `add = points.slice(1).reverse()`（外へ向かって描いた線を、ルートの向きにする）。`old` の先頭に時刻があれば、`[...add, old の先頭]` の所要時間を B3 で求め、`old の先頭の時刻 − 所要時間` を開始時刻として時刻を付け、末尾（= `old` の先頭）を除く。`[...add, ...old]` | ルートに追記 |
| `replace` | `mid = points.slice(1, -1)`。両端（`old[startIndex]`・`old[endIndex]`）の両方に時刻があれば、`mid` の各点に、両端の間の道のりの比で時刻を付ける（道のりは、`[old[startIndex], ...mid, old[endIndex]]` の大円距離の累計）。`[...old.slice(0, startIndex + 1), ...mid, ...old.slice(endIndex)]` | 道なり補正 |

- 行き先のルート・トラックが無い、`replace` の番号が範囲の外のときは `target-missing`（何も変えない。パネルがトーストで知らせ、下書きは残す）
- 元の `routes`・点のオブジェクトを書き換えない（変わったルートとトラックだけを新しく作る）
- `points` の先頭（`replace` は末尾も）は、行き先の端の点と同じ位置のはず。位置が違っていても、捨てて元の点を使う

単体テスト（`tests/draftApply.test.ts`）: 上の 4 つの行き先 × 時刻あり・なし、`head` の向きと時刻（先頭の時刻より前で、単調に増える）、`replace` の両端の点が元のオブジェクトと同じ内容（ウェイポイント・`_extensions` を保つ）、`startIndex + 1 === endIndex`（間に点を足すだけ）、`target-missing`、元の配列が変わっていないこと。

### 10.3 自動保存（C1）に入れる下書きの形

```ts
interface SavedDraft { version: 1; mode: 'create' | 'reroute'; target: DraftTarget; draft: Draft }
```

- `pending` の区間は、そのまま保存する。復元したとき、`pending` の区間を頼み直す（取り消しと同じ手順。§8.4）
- 履歴（`draftPast`・`draftFuture`）は保存しない

## 11. 利用者ごとの設定（承認の条件）

静的サイトでアカウントが無いので、「利用者ごと」= **ブラウザごと**に `localStorage` へ保存する（キー `geoedit-routing`。§8.3 の `routingEnabled`・`routingOptions` もここに入れる）。

### 11.1 設定の項目

```ts
// src/lib/routing/settings.ts（純粋。DOM に依存しない。読み書きは呼ぶ側）
export type PriorityPreset = 'strong' | 'standard' | 'weak' | 'shortest' | 'custom'
export interface RoutingSettings {
  version: 1
  enabled: boolean                      // 経路探索（既定 true）
  avoidMotorway: boolean                // 高速を使わない（既定 false。D4）
  avoidToll: boolean                    // 有料道路を使わない（既定 false）
  preset: PriorityPreset                // 優先の強さ（既定 'standard'。D3）
  weights: [number, number, number, number, number, number]   // 里 / 市 / 県 / 国 / 有 / 高。preset が custom のときだけ使う
  valleyPenaltyM: number                // 抜け道の罰則（1 段あたり m 相当）。custom のときだけ使う
  snapRadiusM: number                   // 道へ寄せる距離（既定 30）
  snapMotorwayBiasM: number             // 高速・トンネルの不利（既定 15。D5）
}
export const DEFAULT_ROUTING_SETTINGS: RoutingSettings
export function presetParams(preset: Exclude<PriorityPreset, 'custom'>): { weights: RoutingSettings['weights']; valleyPenaltyM: number }
export function resolveSearchParams(s: RoutingSettings): SearchParams       // preset → 重み・罰則、avoid → maxClass
export function sanitizeSettings(raw: unknown): RoutingSettings            // 壊れた・古い・範囲外の値は、項目ごとに既定値へ戻す
```

| プリセット | 重み（里 / 市 / 県 / 国 / 有 / 高） | 罰則（m / 段） | 意味 |
|---|---|---|---|
| 強い | 12 / 6 / 3.2 / 2.0 / 1.3 / 1.0 | 5,000 | 上位の道へ大きく回る |
| **標準（既定）** | 8 / 4 / 2.4 / 1.6 / 1.2 / 1.0 | 2,000 | 承認した値（D3） |
| 弱い | 3 / 2 / 1.5 / 1.25 / 1.1 / 1.0 | 500 | 少しだけ上位を好む |
| 最短 | 1 / 1 / 1 / 1 / 1 / 1 | 0 | 道のりが最短（階級を見ない） |
| カスタム | 利用者が入れる | 利用者が入れる | |

範囲（`sanitizeSettings` が守る）: 重みは 1.0〜20（小数 2 桁）、罰則 0〜20,000、寄せる距離 5〜100、不利 0〜50。

- 変えられないもの: 階級の決め方（§2.2）、谷の数え方（§4.3 の `valleyFloor = 2`）、長い区間の値（§6.4）。これらは設計の前提で、利用者が変えても良くならない
- **A* の下限**は、使える階級のうち最小の重みで計算する（§4.2）。重みを利用者が変えても、下限が過大にならない（最適性を保つ）

### 11.2 画面

- 作成モードのパネルの「経路探索」チェックボックスの横に、歯車のボタン（`Settings2` アイコン。`aria-label="経路探索の設定"`）。押すと、既存の `Modal` で「経路探索の設定」を開く

- ダイアログの中身: 優先の強さ（ラジオボタン 5 つ。カスタムのときだけ、重み 6 つと罰則の数値の入力欄を開く）、道へ寄せる距離、高速・トンネルの不利、「既定に戻す」ボタン、「閉じる」
