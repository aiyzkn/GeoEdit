## 1. 最初にやること

1. この文書を最後まで読む
2. 指令リポジトリ（`aiyzkn/loop-control`）の `projects/geoedit/project.md` と、自分が着手するタスクのファイル（§3 の表）を読む。**着手の条件・承認の記録は、タスクのファイルが正**

4. `npm ci`（`node_modules` は無い）→ `npm run build`・`npm test`・`npm run test:e2e` が、手を入れる前に通ることを確かめる。通らないものがあれば、手を入れる前に記録する
5. 着手する WP の、設計書の該当する節を読む。「未確認」と書いてある項目は、実装の前に確かめる（§5）

### 3.2 勧める順

同じファイル（とくに `EditModePanel.tsx`・`editorStore.ts`・`EditToolbar.tsx`）を多くの WP が触る。**並行で進めず、1 本ずつ PR にして、前の PR の上に積む**。

2. C3  確認ダイアログ              （独立。小さい。B1・E2 が使う）
3. A-0 事前検証（スパイク）        （結果で A の数値が決まる。設計書に書き戻す）

7. B3・B4  時刻の速度・形を保つ間引き
8. B5  作成中の標高グラフ・距離
9. B0・B1・B2  下書きの行き先・道なり補正・追記
10. C1・C2  自動保存・離脱の警告

### 3.3 PR の単位

- 上の番号 1 つが PR 1 本（7・9・10・12・13・14 は、項目ごとに分けてもよい）

## 6. コードについて、知っておくこと

読んで分かったこと。設計書に散らばっているものを、ここにまとめる。

- **`EditModePanel` は、アプリ全体で 1 回だけマウントされ、モードを替えても作り直されない。** `useState` の初期値は、最初の 1 回しか効かない。モードに入るたびの初期化は `useEffect([mode])` で行う（既存の `rename`・`create` がその形）
- **Zustand のストアは `window` に出していない。** E2E は、見える結果（トースト・ルート一覧の「n pts」・統計の値）で確かめる。セレクタは、文言・`title`・`role="dialog"`・Leaflet のクラスの順（`tests/e2e/helpers.ts` の冒頭の方針）。`data-testid` を足すなら、まとめて方針を変えることになるので、PR を分ける
- **E2E は、タイルなどの外部の取得を、`helpers.ts` でモックしている。** ベクトルタイル（`.pbf`）・標高タイルの URL を足すこと。経路探索の E2E 用に、小さな道路網の `.pbf` を作って `tests/e2e/fixtures/` に置く（実タイルを保存して使うなら、出典を書く。数十 KB まで）
- **`src/lib/mapMatch/` の中は、`@/` のエイリアスを使わない**（`node --test` から直接 import するため。`types.ts` の冒頭に理由がある）。`src/lib/routing/` も同じにする。単体テストは `tests/*.test.ts`（`tests/register-alias.mjs`・`alias-hooks.mjs` を見ること）
- **`CreateRouteLayer` は、状態が変わるたびに、すべてのレイヤーを消して作り直している。** ドラッグ中に状態を変えると、つかんでいるマーカーが消えてドラッグが切れる。A-2 で、マーカーを使い回す形（`id` で対応づけて、位置だけを動かす）に直す。ドラッグ中の仮の線は、ストアを通さず、レイヤーを直接動かす
- **作成中の Undo は、ルートの Undo と別の仕組み。** `useKeyboard` が、作成モードで未確定の点があれば先に取り消す、という分岐を持つ。A-2 で履歴の形を変えるとき、この分岐と、ヘッダーの「元に戻す」ボタン（`AppHeader.tsx` の `handleUndo`）の両方を直す
- **ルートの Undo は、`pushUndo(説明, 変更前の routes)` を、変更の直前に呼ぶ形**（`structuredClone` で複製される）。新しい操作も同じ形にする
- **時刻は `Date`。** `structuredClone`・IndexedDB はそのまま通るが、JSON にすると文字列になる
- **地図をクリックしたときの、マップマッチングの順序を保つキュー**が `MapPane.tsx` にある（マップマッチング設計書 §5.2）。アンカーの追加は、この順序の保証を保つ
- **地図の入れ物に `isolate` が付いている**（Leaflet の高い `z-index` を閉じ込めるため。基本設計書 16.1）。地図の上に重ねる UI を足すときは、この外に置く
- **「部分編集」は、点ごとにマーカーを出す別の仕組み**（最大 601 点）。B1（道なり補正）は、これを変えずに、別のモードとして足す
- **ルートを作る ID は `crypto.randomUUID()`**、名前の重複は `isRouteNameTaken()` / `makeUniqueRouteName()`
- コメント・コミット・PR は日本語。既存のコメントは「なぜそうしたか」を書く流儀なので、合わせる

## 7. 設計から外れるとき

- §2.2 の範囲（設計者の判断）: 変えてよい。設計書の該当する節を直し、その設計書の末尾に「変更の記録」の表（日付・節・何を・なぜ）を作って 1 行足す。PR の説明にも書く
- §2.1 の範囲（利用者の決定）・§2.3（やらないこと）に触れる: 変えない。タスクのファイルの「利用者への質問と回答」に書き、`status: waiting` にして、関係しない部分を進める
- 設計書に書いていないことを決める必要が出た: 小さければ決めて、設計書に書き足す。利用者から見える動きが変わるものは、既定の案を付けて質問に書く
- 「未確認」が、設計の前提を崩す結果になった（例: 中心線がつながらない・CORS で読めない）: その WP を止め、分かったことと代わりの案を、タスクのファイルと設計書に書いて、利用者に報告する

## 付録 A. ベクトルタイルを調べるスクリプト

設計の時に使ったもの（Node 20。`npm i @mapbox/vector-tile@1.3.1 pbf@3.2.1` をした作業用のフォルダで動かす）。経度・緯度とズームを変えて、`road` レイヤーの属性の値の種類と、端点の重なりの数を出す。事前検証 1・2・4・5 の出発点にする。

```js
// probe.mjs
import { createRequire } from 'module'
const require = createRequire(import.meta.url)
const { VectorTile } = require('@mapbox/vector-tile')
let Pbf = require('pbf'); Pbf = Pbf.default ?? Pbf
const lon = 139.774, lat = 35.684            // 日本橋付近
for (const z of [16, 14, 12, 9]) {
  const n = 2 ** z
  const x = Math.floor((lon + 180) / 360 * n)
  const y = Math.floor((1 - Math.asinh(Math.tan(lat * Math.PI / 180)) / Math.PI) / 2 * n)
  const res = await fetch(`https://cyberjapandata.gsi.go.jp/xyz/experimental_bvmap/${z}/${x}/${y}.pbf`)
  const buf = new Uint8Array(await res.arrayBuffer())
  console.log('==', z, x, y, res.status, buf.length, 'bytes')
  if (!res.ok) continue
  const tile = new VectorTile(new Pbf(buf))
  const road = tile.layers.road
  if (!road) continue
  const vals = {}; const ends = new Map()
  for (let i = 0; i < road.length; i++) {
    const f = road.feature(i)
    for (const [k, v] of Object.entries(f.properties)) {
      vals[k] ??= {}
      if (Object.keys(vals[k]).length < 12 || vals[k][v]) vals[k][v] = (vals[k][v] || 0) + 1
    }
    for (const g of f.loadGeometry()) for (const p of [g[0], g[g.length - 1]]) {
      const key = p.x + ',' + p.y; ends.set(key, (ends.get(key) || 0) + 1)
    }
  }
  console.log('road features', road.length, 'extent', road.extent)
  for (const [k, v] of Object.entries(vals)) console.log(' ', k, JSON.stringify(v))
  const deg = {}; for (const c of ends.values()) deg[c] = (deg[c] || 0) + 1
  console.log('端点が重なる本数ごとの数', JSON.stringify(deg))
}
```

2026-11-15 の出力の要点は、経路探索設計書 §2.3 にある。
