## Claudeの思考

### 機能面の棚卸し

ツールバー・各ストア・編集ロジックを読み、テスト可能な操作面を洗い出した。
編集モードは大きく2種に分かれる：
- **パネル操作のみで完結**：逆順・間引き・時刻編集・名前変更・結合・出力
- **ポイント選択が必要**：分割・区間削除・詳細（地図canvasは掴めない）

後者は **タイムラインのカード（`#0`, `#1` … のテキストを持つ通常のDOM要素）** をクリック
することで、canvas を触らずにポイント選択できると分かった。これを
`selectTimelinePoint()` ヘルパーに切り出し、分割・区間削除・複数選択削除に流用した。

### 共有方針の集約（helpers.ts）

横展開時の実装漏れ（特に外部ネットワークモックの呼び忘れ）を防ぐため、方針とヘルパーを
`helpers.ts` に集約した：`setup()`（goto＋モック）, `mockExternalNetwork()`,
`openFilesViaButton()`, `dropFileOnMap()`, `selectTimelinePoint()`, `selectMode()`,
`switchTab()`。冒頭コメントに「E2Eとユニットの役割分担」「セレクタ優先順位」
「状態は見える結果（トースト・点数表記・カウンタ）で検証する」考え方を明記した。

### ドラッグ&ドロップの実装

Playwright には本物のファイル D&D のショートカットが無いため、ブラウザ内で
`DataTransfer` を組み立て、Leaflet コンテナへ `dragover`→`drop` を dispatch する方式で
`MapPane` の `onDrop` 経路を検証した。

### テストで判明した実挙動（ハマりどころ）

1. **`getByText` / `getByTitle` は既定で部分一致**。
   - `getByTitle('削除')` がツールバー「区間削除」に誤マッチ（DOM上先に来る）→ `exact: true`。
   - `getByText('2 ルート')` が読み込みトースト「（2 ルート）」と二重マッチ → `exact: true`。
2. **Point-only ファイルは既定の「トラックとして開く」でトラックへ変換される**
   （`convertRouteKind`）。パーサーは `waypoint` として読むが `loadFiles` が `openAsKind`
   （既定 `track`）で変換するため、`waypoints.geojson` は "2 pts · 1 trk" になる。
   ウェイポイントのまま読むには種別指定が必要、と2テストに分割して固定化した。
3. **タイムラインの数値入力・スクロールバーがセレクタと競合**。属性パネルの標高欄は
   `step="0.1"`（タイムラインの緯度経度は `step="0.000001"`）で特定。透明度スライダーを
   数える `input[type=range]` はルート未読込状態で行う（タイムラインのスライダーと干渉させない）。
4. **標高グラフは既定で表示 ON**（`mapStore.showElevation` 初期値 true）。recharts の
   描画SVGは headless でサイズ測定に依存し不安定なため、トグルボタンのアクティブ状態
   （`text-blue-500`）で検証する方針に切り替えた。

### 作成モード（唯一の地図クリック）

`create-route.spec.ts` のみ地図canvasをクリックする。マップマッチングのタイル画像解析
（非同期・タイルモック依存）を避けるため **Ctrl+クリック**（マッチングをスキップする修飾）で
座標を決定的にした。未確定ポイント破棄の確認ダイアログ（`window.confirm`）は
`page.once('dialog', …)` で dismiss/accept 両経路を検証した。

## 実行した操作

1. `Read` 多数（EditToolbar / 各 store / routeEditors / VirtualTimeline / 各パネル /
   PlaceSearch / parsers / serializers / AppLayout 等）で操作面と文言を確認
2. `Write` → `helpers.ts`、フィクスチャ7点、スペック8本、`smoke.spec.ts` 再構成
3. スペック単位で `npx playwright test <name>` を回し、上記ハマりどころを順次修正
4. フルスイート `npx playwright test` を反復し **全49件緑化**
5. `npm test`（ユニット19件）・`npm run build` の非退行を確認

## 応答の要点

スモーク1本を土台に、ファイル読込・エクスポート・ルート一覧・編集操作・Undo/Redo・
パネル/レイヤー・UI・ルート作成の8スペック（計49ケース）へ横展開した。共有方針は
`helpers.ts` に集約し、後続の追加が容易な構成にした。アプリ本体のソース変更なし。
発見した実挙動（部分一致セレクタ・種別変換・既定ON要素等）はコメントとして記録した。
