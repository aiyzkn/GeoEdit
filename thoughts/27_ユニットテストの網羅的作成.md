## Claudeの思考

### テスト設計の方針（E2E との役割分担）

- **E2E**: UI操作の導線（ボタン→状態反映）
- **ユニット**: パーサー/シリアライザ/幾何/統計/編集アルゴリズムの入出力を境界値込みで検証

既存ユニット（`matcher.test.ts` / `palette.test.ts`）と同じ流儀＝ `node:test` +
`node:assert/strict`、相対 `.ts` import、Node の型ストリッピングでビルド不要、を踏襲した。

### 技術的制約：DOM 依存モジュールの除外

GPX/KML パーサーは `DOMParser`（ブラウザAPI）依存で `node:test` では動かせない。
これらは E2E 側でカバー済みと整理し、ユニットの対象から外した。
GeoJSON パーサーは `JSON.parse` のみで DOM 非依存のため対象に含めた。

### 技術的制約：`@/` パスエイリアスの解決

`routeEditors` / `routeStats` / `gpxSerializer` はソース内で `@/lib/*` の**値インポート**を
持つ（型のみの `@/` import は型ストリッピングで消えるので問題ない）。Node は tsconfig の
`paths` を読まないため、これらを直接 import すると `ERR_MODULE_NOT_FOUND` になることを
実測で確認した。

対応として最小の ESM resolve フックを追加した：
- `tests/alias-hooks.mjs`：`@/x` を `<repo>/src/x` へ写像し、拡張子が無ければ `.ts` /
  `index.ts` を補完する `resolve` フック
- `tests/register-alias.mjs`：非推奨の `--loader` を避け `module.register()` で登録
  （子テストプロセスへも伝播）
- `package.json` の `test` を `node --import ./tests/register-alias.mjs --test "tests/*.test.ts"` に更新

既存テスト（相対 `.ts` のみで `@/` 値依存なし）には影響しないことを確認した。

## 応答の要点

純粋ロジック6モジュールに新規97件のユニットテストを追加し、既存19件と合わせ全116件が
パス。DOM 依存の GPX/KML パーサーは E2E に委ね対象外とした。`@/` エイリアスを解決する
最小 ESM フックを導入し、既存の `node --test` 流儀を維持したまま値インポート依存モジュールも
テスト可能にした。アプリ本体のソース変更なし、ビルドも非退行。
