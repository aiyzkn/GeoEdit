# ターン 02：要件定義書の作成

**日時**: 2026-06-30
**出力ファイル**: `requirements/要件定義書.md`

---

## ユーザーのプロンプト

```
これをもとに、Leafletで実現可能な要件を抽出して、要件定義書に記載します。
./requirements/要件定義書.md に書き出します。必要に応じて私に質問してください。

- 対応ファイル形式: GeoJSON, GPX, KML
- UI: ビデオ編集ソフトのような2ペイン構成で、メインペインに地図、下部ペインに
  タイムライン（時系列でインデックス番号、ID、時刻、座標などを並べた横リスト）を表示
- 地図には国土地理院の地理院タイル（標準）を使うが、レイヤーを切り替えられるようにする

他にも追加した方が良い機能があれば提案してください。
```

## Claudeの思考

### 参考 URL の取得

SPA のため HTML レンダリング後のコンテンツが取得できず、最小限の情報しか得られなかった。
しかし後のターン（ターン 03）でタイル一覧を追加更新することになるので、
このターンでは既知の国土地理院タイルを代表的なものとして記載するにとどめた。

### 「Leaflet で実現可能な要件」の解釈

Leaflet はあくまで地図表示ライブラリであり、編集ロジック自体は JavaScript で実装する。
「Leaflet で実現可能か」という問いに対しては、
「地図インタラクション部分が Leaflet の API で実装できるか」と読み替えた。

参考サイトの全 16 機能はいずれも Leaflet の
- `L.Polyline` / `L.Marker`（ルート・マーカー描画）
- `draggable` マーカー（ポイント移動）
- `click` / `contextmenu` イベント（ポイント操作）
- `L.control.layers`（タイル切り替え）

で実現可能と判断し、「Leaflet では実現不可能な機能」は存在しないと結論付けた。

### 確認すべき未決事項の選定

要件定義書を書く前に決めるべき曖昧な事項を洗い出した。

| 項目           | 曖昧さの理由                                                         |
| -------------- | -------------------------------------------------------------------- |
| 出力形式       | 入力が 3 形式なら出力も 3 形式にすべきか、GPX のみで良いかは方針次第 |
| Undo/Redo      | 実装コストが高く、要否はユーザーの優先度次第                         |
| 標高グラフ位置 | タイムラインと同一ペインにするかは UI 設計に大きく影響する           |
| モバイル対応   | ターゲットがハイカーなら重要。PC ツールとして割り切るかも不明        |

これらを `AskUserQuestion` で確認することにした。

### 質問の設計

4 問すべてにプレビュー機能（モーダルの `preview` フィールド）を活用するか検討したが、
標高グラフ位置のみ ASCII ワイヤーフレームによる視覚的比較が有効と判断して
`preview` を設定した。他の 3 問はラベルと説明文のみで十分と判断した。

### 回答を受けての要件定義方針

| 質問         | 回答                            | 設計への反映                                   |
| ------------ | ------------------------------- | ---------------------------------------------- |
| 出力形式     | GPX / GeoJSON / KML の全 3 形式 | セクション 9 にオプション分岐で記載            |
| Undo/Redo    | 必要                            | セクション 8 として独立、50 ステップ上限を設定 |
| 標高グラフ   | On/Off ボタンで切り替え         | タイムラインの上部に折り畳み                   |
| モバイル対応 | PC 優先、最低限                 | セクション 14 の非機能要件に記載               |

### 追加提案機能の選定

参考サイトにない機能として、以下を要件定義書のセクション 11 に追加提案として記載した。

- **統計情報パネル**: 総距離・累積標高差・速度など → ルート活用時に必須の情報
- **地名検索**: 国土地理院ジオコーダー API → 山域への素早いナビゲーション
- **タイムライン複数選択・一括削除**: Shift/Ctrl+クリック → 大量ポイント間引き操作を効率化
- **ルート表示色カスタマイズ**: 複数ルート比較時の可読性向上

## 応答の要点

- 要件定義書を 14 セクションで構成（概要〜非機能要件）
- 参考サイトの全編集機能を Leaflet 実現可能と判断して全採用
- タイムライン仕様を詳細に定義（仮想スクロール・双方向同期・表示項目）
- セクション 5 ではこの時点で判明している代表的タイルのみを記載（次ターンで拡充）
- 非破壊編集・ブラウザのみで動作・ネット接続必要、の原則を明示
