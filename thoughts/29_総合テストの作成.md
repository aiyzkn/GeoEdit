## Claudeの思考

### 「総合テスト」の位置づけ（4層目）

既存3層（ユニット＝単一関数／結合＝モジュール連結・ストア状態機械／機能別E2E＝
1機能=1テスト）の上に、**要件定義書の受入シナリオに沿った通しの業務フロー**を置く。

機能別E2Eが部品を個別検証するのに対し、総合テストは「実際の利用の流れ」を端から端まで
なぞる。各ステップに要件定義書の節番号（§x.y）をコメント併記し、要件トレーサビリティを
持たせた。基盤・方針は機能別E2Eと共通（`tests/e2e/helpers.ts` を再利用）で、
配置のみ `tests/e2e/scenarios/` に分離した（Playwright の testDir 配下なので自動収集される）。

### シナリオ選定（要件との対応）

要件定義書の主要章を跨ぐ6本を選んだ：

| # | シナリオ | 対応要件 |
|---|---|---|
| S1 | 読込→逆順→間引き→Undo→GPX出力 | §4 / §6 / §8 / §9 |
| S4 | GPX読込→要素種別変換→別形式エクスポート | §4.5 / §9 |
| S2 | 地図で新規作図→時刻付与→GeoJSON出力 | §6.1 / §6.7 / §9 |
| S3 | 2ファイル→結合→統計確認→再エクスポート | §4.2 / §6.5 / §10 / §12.1 |
| S5 | 標高なし読込→GSI API自動補完→統計反映 | §4.2 / §7 / §12.1 |
| S6 | 地図↔タイムライン↔属性の選択同期と編集の統計伝播 | §3.4 / §7 / §8 / §15 |

3ファイルにテーマ別（編集ログ／作図・結合／解析・同期）で分けた（並列実行・可読性）。

### 検証を「通し」で意味あるものにする工夫

- **S1**: 逆順→間引き→Undo と連続操作した後の**最終状態**を出力内容で検証（逆順による
  時刻除去・順序反転が残り、間引きだけが Undo で戻る）。個別E2Eでは見えない
  「操作の積み重ね順」を固定化できる。
- **S3**: 結合後に「1ルート・6点・2トラック」→統計→GPX再出力（trkseg×2 / trkpt×6）まで
  一貫確認。
- **S6**: タイムライン選択→属性表示→インライン編集→統計伝播→Undo戻し、と1ジャーニーで
  3面同期を追う。

### 外部依存・canvas 操作の扱い（既存方針を踏襲）

- 外部API（タイル/標高/地名）は `setup()` の既定モックで全遮断しネットワーク非依存。
- S5 の標高自動補完経路を発動させるため、**標高を1点も持たない** フィクスチャ
  `no-elevation.gpx` を新設（既存 `notime.gpx` は標高付きで発動しない）。モックが
  `getelevation.php` に `elevation=10` を返すので、補完後は全点10m→統計「10 m / 10 m」で検証。
- S2 の作図は Ctrl+クリック（マップマッチングのタイル解析をスキップ）で座標を決定的化。

## 応答の要点

要件定義書の受入シナリオに沿った総合テスト6本を `tests/e2e/scenarios/` に追加した。
各ステップに要件節番号を併記し要件トレーサビリティを付与。既存E2E基盤を再利用し、
標高補完用フィクスチャ1点のみ新設。これでテストは4層（ユニット/結合＝`npm test` 147件、
機能別E2E/総合＝`npm run test:e2e` 55件）に揃った。アプリ本体のソース変更なし、
全テスト・ビルドとも非退行。
