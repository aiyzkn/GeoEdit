## Claudeの思考

### 機能 1：ルート描画色の変更

**実装方針の選択**:

選択肢 A: カスタムドロップダウン（プリセット色のスウォッチ一覧）  
選択肢 B: ブラウザ標準の `<input type="color">`  
→ **B を採用**。理由：
- ブラウザ標準なので OS ネイティブのカラーピッカーが開き、任意の色を選べる
- 実装がシンプル（隠し input を透明なオーバーレイとして配置するだけ）
- ライブラリ追加不要

**実装の詳細**:
```html
<div class="relative w-4 h-4 ...">
  <!-- 見た目 -->
  <div class="absolute inset-0" style="background-color: {color}" />
  <!-- 機能（透明オーバーレイ） -->
  <input type="color" value="{color}" class="absolute inset-0 opacity-0 cursor-pointer" />
</div>
```
クリックすると透明な `input` がヒットして OS のカラーピッカーが開く。

**色の一元管理**:
`MapPane.tsx` と `RouteList.tsx` が同じデフォルトパレットを使っていた。
重複を避けるため `src/lib/colors.ts` に `ROUTE_COLORS` 配列と `routeColor()` ヘルパーを切り出し、両コンポーネントが import する設計にした。

**色変更の伝播フロー**:
1. カラーピッカーで色選択 → `onChange`
2. `updateRoute(id, r => { r.color = value })` → immer で store 更新
3. `MapPane` が再レンダリング → `RoutePolyline` に新しい `color` prop が渡る
4. `RoutePolyline` の `useEffect([..., color])` が再実行 → ポリライン色が更新

Undo 対象にしない判断：色変更は軽微な操作であり、Undo スタックを消費させるほどの
重要度はないと判断した。

### 機能 2：バージョン情報ダイアログ

**アイコン位置の判断**:
「`?` アイコンの横に情報アイコン」という要件なので `?` の左（内側、テーマトグルの右）に配置。
`ℹ`（`Info` from lucide-react）を使用。

**ダイアログの内容設計**:
- アプリ名 + バージョン番号（`version.ts` から動的取得）
- 技術スタック一覧（ハードコード — 変更頻度が低いため）
- 変更履歴 (`CHANGELOG` 配列をマップして描画)

**ダイアログの状態管理**:
`uiStore` の `showHelp` と同じ設計で `showAbout: boolean` と `setShowAbout()` を追加した。
ただし `AboutDialog` は `AppHeader` 内でのみ使われるため、`uiStore` ではなく
`AppHeader` のローカル state `useState(false)` で管理する方が適切と判断した。
（理由：他コンポーネントから `showAbout` を参照する必要がない）

`uiStore` にも追加したが、実際は `AppHeader` のローカル state を優先使用している。

### 機能 3：バージョン管理ファイル

**セマンティックバージョニングの解釈**:
ユーザーの「0.0.1からはじまる」という説明と「互換性のない大規模更改.一般的な機能追加.バグフィックス」という説明から `MAJOR.MINOR.PATCH` を採用。

**初期バージョンの決定**:
- `0.0.1` = 最初の設定ファイルだけのコミット
- `0.1.0` = 今回の実装（GPX/GeoJSON/KML 全対応・地図・タイムライン・標高グラフ・編集機能群）という位置付けにした

機能追加（カラーピッカー・バージョンダイアログ）も同じセッション内での実装なので、
すべてを `0.1.0` の初回リリースとしてまとめた。

**`CHANGELOG` 配列の設計**:
```typescript
export interface ReleaseEntry {
  version: string
  date: string
  type: 'major' | 'minor' | 'patch'
  notes: string[]
}
```
型を付けることで、次回バージョンアップ時にフォーマットの一貫性が保たれる。

**`AboutDialog` との接続**:
`version.ts` を import して `APP_NAME` / `APP_VERSION` / `CHANGELOG` を描画に使う。
`version.ts` のみ更新すればダイアログが自動反映される設計。
